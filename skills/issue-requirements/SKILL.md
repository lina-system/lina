---
name: issue-requirements
description: Use when a development request lacks a usable scope or done condition.
---
<!-- SPDX-License-Identifier: Apache-2.0 -->

Read the request, relevant design and existing work before asking for details.
Identify gaps in outcome, scope, acceptance and constraints. Ask only about gaps
whose answers would change what is built or how it is accepted; suggest a
reasonable default with each question.

Turn the intent into a work definition with a concrete outcome, boundaries and
observable acceptance. Keep unresolved assumptions explicit. Prefer the
person's language to internal implementation terminology, and avoid inventing
edge cases that do not affect the outcome. Explain the most consequential
remaining ambiguity. Core validates the required definition fields; deciding
whether those fields express the person's intent remains a judgment.
