# Changelog

All notable changes to LINA are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow
[docs/versioning.md](docs/versioning.md): `0.0.1-alpha.YYYYMMDD.N` during the alpha.

Hermes Agent upstream changes are not listed here; see the upstream history on the `upstream` branch.

## [Unreleased]

### Fixed

- Person devices in work settings now require and accept their status SSH alias (`host`) with `role: person`, while refusing node fields, so saved person devices appear in the devices view (lina#373).
- A gateway started under test isolation stays a plain child instead of a launchd job: `start_gateway_job` returns `None` without a single `launchctl` call while `HERMES_TEST_ISOLATION` is set, so the e2e history tests no longer leave `com.nousresearch.lina.runtime.*` jobs in the developer's own `gui/<uid>` domain, outside the sandbox and out of the test's process tracking (lina#372).
- `lina migrate memory` no longer refuses a profile with a shared skill linked into `skills/`: a symlink inside `skills/`, `memories/`, `memory/` or `personas/` is skipped without reading its target and listed in the report's `skipped_symlinks`; a symlinked profile directory, `state.db` or `lcm.db` is still refused (lina#366).
- `lina store reembed --source messages` gives the vectors of shared external messages (NULL `agent_id`, `scope = 'agents'`) the shared owner `*` instead of the string `'None'`, and migration 0009 lets every agent read them (SELECT-only, as 0005 does for the messages) and gives that owner to vectors already written with `'None'`, so the memory search's vector leg and `lina memory eval-search` find them as any agent (lina#364).
- A parked kanban card no longer waits forever on an event that cannot come: a wait on a card archived unfinished or deleted, or one that could not be read 30 ticks in a row (a PR wait whose gh login cannot read the repository), becomes a `needs_input` block naming why; `kanban.planned_stop_total_limit` (default 20) bounds planned stops between waits; a reviewer run's manual schedule returns to review on unblock; and the `kanban_block` tool takes `wait_for` like `kanban block --wait-for` (lina#258).
- `scripts/sync-upstream` merges with git's directory-rename detection off, so an upstream file new under a pruned directory is pruned instead of being moved into a kept directory with similar files (a subtree) as a conflict; merging Hermes `main` at 6b21d0564d into `dev` leaves 30 conflicts instead of 179 (lina#4).
- ACP worker execute requests with a missing or empty `cwd` use the session's work folder for access checks; explicit outside paths and read-only execution stay denied, and permission events record input key names without values (lina#352).
- `hermes kanban boards rm` of a pinned worker's own board whose `kanban.db` links to the pinned database archives it and leaves the `archived` tombstone instead of failing after the move, and two kanban tests no longer fail on a Mac outside CI: the `enable-linger` spawn-refusal test is marked Linux-only, the dispatcher probe writes its config with the current `_config_version`, and the gateway test probes' child gateway no longer reads the account's launchd/systemd for a loaded Hermes Agent gateway (lina#259).
- The board's worker views (`worker_read`, `devices_read`) and its live run-event stream read the root `lina worker` writes, `settings.lina_home()` (`LINA_HOME`, and a `HERMES_HOME` of Hermes Agent's ignored for the platform default), through one helper rather than a second rule, so a Hermes card session or a `LINA_HOME` that differs from `HERMES_HOME` no longer shows no runs, no devices and no run events for work that is running; the board's work, quota, read-mark and settings readers keep their own root (lina#269).
- A work card on LINA's own board finishes only when every `lina worker` run it started has a verdict (accept, reject or cancel): `complete`, `request_review` and a goal judge's done are refused naming the runs (operator override `--allow-unjudged`, recorded on the card); a run's end or question lets a card waiting behind an unfinished parent or on a schedule judge it and then wait again; a run left unjudged for an hour is raised once on its card (or the starting agent's main session when the card is gone), a pause with no reopen condition once after a day, and the board API marks runs waiting on an agent's verdict `waitingOn: agent:<name>` and counts them under that agent (`counts.agents`), never in the owner's inbox (lina#295).
- The hub wakes a Hermes card with `kanban unblock --judge-wake <run id>` (the batch ID for an `OG-` batch) so it lands `ready` to judge the run even behind an open parent, falling back once to a bare `unblock` on a Hermes without that option and recording the form in the `card_noticed` receipt; every hub job on a Hermes card carries `cards: [{id, board}]` for Hermes's unjudged-run guard (lina#341).
- `lina services start web` starts on the lina-app build (`LINA_APP_DIST`, else `dashboard.app_dist`, read as the dashboard reads it) and refuses in one line when that folder has no `index.html`, instead of refusing for the Hermes dashboard UI (`hermes_cli/web_dist`) that no install has since `web/` left dev; the job no longer passes `--skip-build` or `HERMES_WEB_DIST`, so `/` answers 404 per request (lina#338).
- Every `omo-task` caller keeps working through the shim: `lina worker submit|send|wait` take the card from the nearest ancestor process with `HERMES_KANBAN_TASK` (and accept `--card-board`), the owner and the verdict's `by` follow `HERMES_PROFILE`, `HERMES_PROFILE_NAME`, then the caller's Hermes Agent `HERMES_HOME`, the installed shims pin `LINA_HOME`, a card whose last `kanban_schedule` names a run is woken once after the last run it names ends, a question lands on the card once, `worker.hub_rules` reaches hub-node runs, `worker.todo_link` links the to-do, `attach`, `card` and `submit --session` are accepted, and `list` adds the old tool's tasks (lina#287, lina#275).
- The work settings hold on the hub's real paths: a submit in a new process checks the model against `work-settings/models-last-good.json` (the models view's last good read, at most 10 minutes old), `lina work next --submit` passes each issue's labels and size so the `worker.routing` rules choose the runner before its runner label, and behind the hub's own `tailscale serve` the owner-device gate judges the last `X-Forwarded-For` entry of a loopback peer (lina#283).
- `GET /api/lina/usage` no longer waits on per-machine OCX reads: `byMachine` is summed from one `usage --range 30d --api-key-id` read per `link:` key, run one after another in the background at most every 15 minutes and started by a usage read; a failed round keeps the previous rows; and the `ocx status --json` gate of an external OCX serves its last answer while a background read refreshes it at most every 60 s (lina#273).
- A kanban goal-mode card whose judge says WAIT is parked (`scheduled`) on the event it waits for, recorded on the card, and the dispatcher wakes it once when that card is done, that review has its result, that PR's required checks finish or that time passes (`kanban schedule|block --wait-for` record the same by hand); a spent turn budget, runtime limit or agent iteration budget hands off and returns the card to ready without counting toward `max_retries`, and `kanban.planned_stop_limit` (default 5) such stops in a row block the card for a person.

### Added

- The hub drives a goal's work cards by rules in its tick instead of card-session turns: one follow-up for a red required check (named, with its log tail) or a missing deliverable, a `needs_input` block with an inbox line after three follow-ups in one attempt, a run on a lost node started again on another node from its pushed branch only once the device shows it did not continue, a usage-limited run that waits for the reset (or moves with `worker.goal_limits.usage_move`) without counting as an attempt, and parked cards on `--wait-for`; every action carries the id `<goal>:<card>:<attempt>:<run>:<rule>` as its request key, the limits in `worker.goal_limits` (workers 3, attempts 3, runs 40, 24 h) block the goal card with the reason, a runner's `usage_limit` sets its pattern, the drive never completes a card, and `worker.goal_drive: false` switches it off (see [docs/work/goal-drive.md](docs/work/goal-drive.md), lina#225).
- `lina store reembed --source messages --from-index <db>` imports the message collector's stored chunk vectors (its SQLite index, the sqlite-vec `vec0` table read from its 0.1 shadow tables without the extension) with `truncate_stored` instead of re-embedding them, when the index's `meta.vector_model` is the configured model: one `vec.chunks` row (its messages' ids in `ordinal` order) and one 1024-wide vector per chunk, with the shared owner `*`. Chunks with messages not in `memory.messages`, empty chunks, an index of another model and unusable or deleted vectors are counted and left for `reembed`; a rerun inserts nothing; `reembed --source messages` skips and counts the messages an imported chunk covers; model names compare without a provider prefix (`qwen/qwen3-embedding-8b` is `qwen3-embedding-8b`) (lina#365).
- `GET /api/lina/devices` serves each node's role (`work`, `files`), whether it is reachable and one cell per runner with the fleet and installed version, the sign-in state, whether a sign-in this hub started is still running (`signingIn`) and one reason when not ready (omo from a background `lina omo status` read every 10 minutes), and the person devices (`role: person`) with their status and tool versions only, read by one read-only ssh call every 15 minutes; `POST /api/lina/devices/{name}/restart` restarts a node's worker or OCX through its service layer and `POST /api/lina/devices/{name}/sign-in` starts a runner's sign-in (501 until lina#230 lands), both only from the owner's devices and logged to `board/device-actions.jsonl` without any sign-in address, code or token (lina#234).
- File nodes: `devices.workers.<name>.kind: file` drives a machine without LINA, git or a recent Python over ssh (the hub keeps the run state; the node runs omo and a `nohup setsid` bash runner), its `hello`/`probe` report whether the model path through the hub answers and refuse runs while it does not, `role: work|files|person` decides who bidding may pick (`files` only by `--host` and never with a repo, `person` never), and a `deny` list refuses briefs and inputs naming those folders and ends a run as `review` naming the files changed under them (a check, not a sandbox; see [docs/file-node.md](docs/file-node.md)) (lina#229).
- `scripts/ci/check_pruned_imports.py` fails while kept code imports (`import`, `from`, relative, or a string `importlib.import_module`/`__import__`) a module that only upstream files LINA deleted provided; files listed in its exceptions, each with a reason, are reported but do not fail (lina#4).
- `hermes kanban gate ui-qa` counts only the QA side's records: a `ui-qa-result` or `ui-qa-run` comment by the card's own profiles is ignored (and, with `--author <name>`, one by anyone else), with one `note:` line naming each; `kanban plan` refuses a `kind: screen` card whose gates do not run `gate ui-qa` (lina#276).
- `lina worker submit` and `send` take a request key (`--key`, else a new one printed as `request key: <k>`), as do `Hub.submit`/`Hub.send` and every caller in the core (`lina work` uses its outbox row): a retry with the same key and arguments returns the first task and run and starts nothing (receipt `request_replayed`), other arguments are refused, the keys survive a hub restart, and devices keep the keys of `follow_up`, `answer` and `send` (see [docs/worker-protocol.md](docs/worker-protocol.md), lina#219).
- Every end the hub records is one event, on the receipts, the job, the card and the notice (whose first line starts with it): `run.completed` with its end state, `question` or `host.unavailable`; each has one delivery id, kept in `hub/deliveries.jsonl`, so a repeated report (a device retry, the tick, a hub restart) is recorded as `delivery_duplicate` and sent once; an unreachable node is told once per outage after three failed contacts, naming its runs, with one line when it is back, its runs then going back under watch, in place of one `unknown` notice per run, and `worker.unknown_after_s` is gone; see [docs/worker-run-lifecycle.md](docs/worker-run-lifecycle.md) (lina#223)
- `lina services start|stop|restart web` runs the dashboard server of the LINA root as a service (launchd `ai.lina.web`, systemd `lina-web`) on `dashboard.host` / `dashboard.port` (default `127.0.0.1` / `9119`), serving the app build at `/app/`; it never builds the UI and never attaches to or stops another home's dashboard on the account. Every LINA launchd job (`ocx`, `worker`, `web`) starts under `/usr/bin/osascript` with its logs in the LINA root's `logs/`, so a LINA root on an external disk is reachable, and service jobs drop `HERMES_KANBAN_*`, `HERMES_DELEGATED_CHILD_CONTEXT` and a `HERMES_HOME` of Hermes Agent's (lina#288).
- ACP worker runners: `type: acp` with a mandatory `argv` and an optional `flavor` (`grok`, `dsh`, `agy`, `claude`, `codex`; omitted is generic) in the work settings, with access-mode permission answers, no client fs or terminal, `question.md` as `waiting_human`, session load/resume across runs and steering by cancel then prompt (see [docs/worker-protocol.md](docs/worker-protocol.md)).
- `lina runners install|upgrade|rollback|status` pins codex, claude, dsh, grok, cursor-agent, agy and the Claude and Codex ACP adapters in `pm/lina-deps.json` and installs each under `$LINA_HOME/vendor/runners` with the installer that owns its binary, checked against its npm integrity or release hash; upgrades trial the new version and switch back on failure, and a runner the person installed is only read. each node's worker `hello` carries its runners with pinned and installed version, sign-in and one reason when not ready, and `lina devices` shows them, `lina devices sign-in` lists one question per runner waiting for a sign-in, and `lina devices service <name> ocx|worker status|restart` goes through each node's `service` verb and service layer (see [docs/lina-runners.md](docs/lina-runners.md), lina#222).
- `lina devices sign-in <node> <runner>` signs Grok or Antigravity in on a node from the hub's signed-in browser. It starts the runner's own sign-in there, hands the address to `worker.sign_in.browser.command` on stdin, carries a `127.0.0.1` return back through `ssh -L`, and reads the node's `hello` again for `signed_in`. A two-step check, a new device or an account choice stops the flow with one inbox question naming the node and the runner. OCX and key runners are only reported, and no address, code or token is shown or kept (see [docs/lina-sign-in.md](docs/lina-sign-in.md), lina#230).
- Worker runs record an access mode, enforce per-agent ceilings and runner-specific permissions without follow-up escalation, and declare device verb effects while keeping push blocked (lina#220).
- Worker contacts negotiate protocol ranges and capabilities before verbs, preserve legacy run recovery, and guard service controls with per-start instance identities (lina#218).
- `lina worker submit` picks the runner (`--runner`, else the routing rules on the new `--labels`/`--size`, else the default; a runner that is off is refused) and the model (`--model`, else the runner's model, else the mode default) from the work settings, starts on the fallback model with one `model_fallback` receipt when OCX has the chosen one off or out of quota, and records the settings revision, both sources and the OCX check on the job and its `submitted` receipt; on the device the job's model wins, and the run record and run card serve `model` and `settingsRevision` (lina#257).
- `hermes kanban gate ui-qa` passes a card that changes a screen only when its PR head has a QA result comment (the aside-qa answer with `ui-qa-result v1 head=<sha> instance=disposable` on top: sections Defects, Verified, Suggestions and Map drift) taken on a disposable instance with zero defects and no `FAIL:` line under Verified; it fails with the defect list, fails on a result for an older head, and waits (exit 75) while a `ui-qa-run v1 head=<sha> state=running` QA run is in progress; the kanban-work-plan skill documents the record and lists `ui-qa` in screen cards' gates (lina#162).
- Work settings: devices and caps, runners and their models, model defaults and fallback and routing rules in the LINA root's `config.yaml` are validated and versioned (`work-settings/revisions`, an audit line per change, one-step rollback, outside edits recorded), edited by `lina worker settings show|set|edit|validate|history|diff|rollback|route|models` and `GET/PATCH /api/lina/work/settings` (writes only from the owner's devices), with OCX's enabled models, their quota left and reset, and a `settings` source on `/api/lina/events` (see [docs/lina-work-settings.md](docs/lina-work-settings.md), lina#256).
- `ocx.external: {cli, data_dir}` in the LINA root's `config.yaml` makes `lina models` and the client API read an OCX run outside LINA, read-only (an argv allowlist, each read cached 60 s, every OCX write verb of `lina models` / `lina services` refused); `GET /api/lina/usage?range=` serves tokens and cost by model, provider, account and machine, `GET /api/lina/models/state` the models on and each machine link's freshness, and `GET /api/lina/quota` adds `left`, account `active`/`state` and the `missing` services (lina#232).
- The shared Desk: `hermes desk init` (run by the installer) creates `~/Desk` with Inbox, Projects, Areas, Resources and Archive, or adopts an existing folder; every agent starts there, and the app reads it from `GET /api/desk` (see [docs/desk.md](docs/desk.md)).
- The memory store: `lina store install` (also run by `lina install`) runs one Postgres with pgvector in Docker, with schemas `memory`, `ctx`, `ltm` and `vec` and row-level security on `agent_id`, and the Honcho api and deriver built from `services/honcho`; `lina store backup` / `restore` back up and restore the whole cluster, and `lina store upgrade` upgrades Honcho by backup, rehearsal migration, one migration job and smoke test (see [docs/store.md](docs/store.md)).
- The delivery procedure of [docs/delivery.md](docs/delivery.md) from the core: `lina work next` lists the issues to open and why the rest waits (`--submit` hands each pick to its runner through `lina worker`), `lina work merge <repo> <pr>` is the only merge path (the gates, a merge commit or the merge queue, then the issue closed and review follow-ups filed; `--branch` lands a worker branch by merging `dev` into it), `lina work status` shows sprint progress per milestone and `lina work sprint current <S>` moves the current sprint.
- The Honcho server v3.5.0 (`plastic-labs/honcho` 0cd37ddbd8) in `services/honcho/`, a squashed subtree tracked by the `honcho-upstream` branch and `services/honcho-intake.md`; CI checks, tests and builds it (see [docs/honcho.md](docs/honcho.md)).
- LCM-X is the core context engine, one copy for every agent: v0.29.1-rc2 (`electricsheephq/lcm-x` 0eb6e8736a) with the `hermes` fork's patches in `plugins/context_engine/lcm-x/`, a squashed subtree tracked by the `lcm-x-upstream` branch; new homes get `context.engine: lcm-x`, its hooks now register, and a `hermes-lcm-x` plugin copy no longer loads beside it (see [docs/lcm-x.md](docs/lcm-x.md)).
- Web Push to the owner's devices: the core pushes a decision to make, an agent's reply to his comment and a work card stopped for him, one notification per item that is replaced on change and closed when the item leaves (`/api/lina/push/*`, see [docs/api/push-client.yaml](docs/api/push-client.yaml)); off unless `LINA_PUSH_VAPID_PRIVATE_KEY` is set in `.env`.
- The hub's own health checks: each check that runs outside the core writes `<LINA root>/status/<name>.json` (`{name, ok, line, at, stale_after}`) and the app reads them from `GET /api/lina/status/checks`, newest first, stale past `stale_after`, a malformed file as one error row (`docs/api/board-client.yaml`).
- `lina worker` takes runs from a Hermes card and reports back on that card (`worker.card_link: {kind: hermes, command: [hermes]}`): the start, the end and `report.md` land on the card through Hermes's own `kanban` command, with no chat notice; `lina worker submit --card <id> --board <slug>` names the card, and `lina worker wait` parks it until the first run end wakes it (see [docs/worker-card-session.md](docs/worker-card-session.md)).

## [0.0.1-alpha.20261102.1] - 2026-11-02

### Added

- Forked from Hermes upstream c7c7e0fa92 (`NousResearch/hermes-agent` `main`, 2026-11-01).
- LINA is licensed under AGPL-3.0-only. Hermes Agent code keeps its MIT License; the notice is in `LICENSES/Hermes-MIT.txt`.
- `hermes --version` reports the LINA version and the Hermes upstream commit.
- The macOS gateway launchd job materializes dataless (on-demand cloud) files when opened.

### Changed

- CI runs only lint, Python tests, lockfile, supply-chain and blob-size checks; the other upstream workflows are kept under `.github/workflows-upstream/` (see [docs/ci.md](docs/ci.md)).
